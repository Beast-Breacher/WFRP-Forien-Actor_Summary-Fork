# Аудит и проверки — 3 ноября 2026

## Изменения 0.1.4-beta.2

Добавлен отдельный CSS override белого цвета текста заголовка сводки (`#fff`). CSS исходного модуля и его source map сохранены. Проверка стиля выполняется на изолированном заголовке в браузере с CSS установленной Foundry 14.369 и WFRP4e; активный пользовательский сеанс ведущего не прерывается. `verified: 14.369` сохранён, версия пакета повышена для штатного обновления метаданных модуля. Старые сведения о совместимости могут оставаться в памяти запущенного сервера после прямой замены манифеста на диске.

## Объект

Пользовательский архив `forien-actors-summary.zip`, Forien's Actors Summary 0.1.3-beta. Это модуль, а не отдельный макрос. Форк 0.1.4-beta.1 сохраняет его архитектуру и интерфейс.

Встроенный runtime не заменён: точечно исправлен его адаптер сохранения настроек. Остальные исправления расположены в прикладном коде и небольшом compatibility helper. Стили, переводы и данные компендия не менялись. Устаревшая JS source map удалена, поскольку после ручных правок она указывала бы неверные строки. Технические `LOCK`/`LOG` исключены, но **`000003.log` сохранён**: это данные LevelDB, а не отладочный лог.

## Проверка в живом мире

После запуска пользователем Foundry модуль установлен штатным установщиком и включён в мире **waha-test**, Foundry **14.369**, WFRP4e **10.1.2**, пользователь Gamemaster. Проверка проведена браузером Playwright с настоящим клиентским API и серверным сохранением, без имитации ядра.

Успешно проверены:

- Автоматическое открытие сводки и открытие конфигурации.
- Настоящий обработчик drop с UUID созданного временного персонажа и игнорирование некорректного JSON.
- Отображение имени, характеристики WS и списка навыков WFRP4e.
- Обновление имени персонажа и характеристики навыка; раскрытие дополнительных данных предмета.
- Изменение числа колонок через интерфейс и чтение сохранённого значения 4.
- Чтение компендия: 3 записи (WFRP4e, DnD5e, PF2e); команды пресетов не запускались.
- Три цикла закрытия/открытия: после закрытия 0 подписок в `actor.apps`, после открытия 1.
- Обработчик кнопки панели `onChange` в обоих направлениях.
- Удаление персонажа при открытом окне, очистка списка и возврат к Drop Actor без ошибки.
- Визуальный осмотр открытых сводки и конфигурации.

В итоговом прогоне ошибок JavaScript страницы и ошибок модуля не было. До включения модуля уже присутствовало сообщение системы `Class WFRP4eActiveEffectModel must define a changes field in its schema`; оно не относится к этому форку. Во время первого прогона попытка переименовать встроенный навык вызвала исключение в `SkillModel._handleSkillNameChange` системы WFRP4e; финальный прогон менял характеристику временного навыка и прошёл. Системный код не изменялся.

Временные персонажи удалены. Значения actors/filters/perRow/openOnStartUp восстановлены. Модуль оставлен включённым в тестовом мире. В манифесте установлено `verified: 14.369`.

## Граница проверки

На ядрах **11–13** живой прогон отдельно не выполнялся: проверены код адаптеров и исходные контракты API. Работа на 14.369 подтверждена перечисленными сценариями, но не длительной игровой сессией и не всеми возможными комбинациями сторонних модулей. Создание/удаление/перестановка фильтров через интерфейс, контекстные меню листов и вход игроком отдельно в живом мире не прогонялись.

Нельзя гарантировать отсутствие ошибок при произвольных пользовательских JavaScript callbacks или сохранность путей `system.*` в новых версиях игровых систем. Callback сохраняет прежнюю семантику: выражение JavaScript с аргументом `item`. Пустой callback по-прежнему не выбирает предметы. Настройки мира общие для ведущих, при одновременной работе действует последнее сохранённое значение.

## Ручной прогон перед стабильным выпуском

Для каждого ядра 11, 12, 13 и 14.369 в отдельном тестовом мире:

1. Установить ZIP, включить модуль, войти ведущим; проверить запуск без ошибок консоли.
2. Открыть/закрыть сводку кнопкой токенов, перезайти в мир, проверить сохранение выбора.
3. Добавить 2–3 персонажей, повторно перетащить одного; изменить имя и предметы, убедиться в живом обновлении.
4. Проверить фильтр `item.type === "skill"`, дополнительные поля, атрибуты, скрытие/перестановку/удаление секций.
5. Поменять быстро несколько настроек, перезагрузить клиент и проверить последние значения.
6. Проверить 1–6 колонок, сворачивание карточек, Collapse All, контекстное открытие листов.
7. Удалить персонажа из мира при открытой сводке; закрыть и открыть окно несколько раз, проверить отсутствие ошибок/роста подписок в `actor.apps`.
8. Перетащить текст, Item и запись компендия: окно продолжает работать. Импортировать персонажа из компендия и добавить уже из Actors.
9. Открыть компендий Filter Presets, проверить чтение и применимость нужных пресетов к установленной системе.
10. Войти игроком: кнопка и автоматическое открытие отсутствуют. Проверить переход с оригинала с сохранением существующих настроек.

После успешного прогона на целевом ядре обновить `compatibility.verified`, версии обоих JSON и выпустить новый тег. Дополнительные версии Foundry выше 14 требуют отдельной проверки: окно остаётся на ApplicationV1.
